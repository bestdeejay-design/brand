# tools — сборка и проверка иконок

Инструменты, которыми знаки из [`../signs/`](../signs/) превращаются в `.icns` и
проверяются. Одна реализация на весь зоопарк. F-1 отозвана: прежний цветной
шум был ошибкой распаковки, а не порчей записей.

## Запуск

```bash
npm ci                        # зависимости по локу (Node 18+)
node tools/build-icons.mjs     # собрать все знаки, проходящие канон
node tools/build-icons.mjs dajet-editor   # собрать один знак
node tools/check-icons.mjs     # проверить все знаки с AppIcon.icns
node tools/check-icons.mjs dajet-editor   # проверить один
node tools/check-icons.mjs signs/dajet-player/AppIcon.icns  # конкретный файл
npm test                      # регрессии полной канвы, старой сетки и радиусов
```

То же самое коротко: `npm run build`, `npm run check`.

`check-icons.mjs` печатает по каждой записи сторону, доли плиты, знака и чужого
цвета и **возвращает ненулевой код выхода**, если запись пустая, шумная или
нарисована не так, как вектор. `build-icons.mjs` возвращает ненулевой код, если
знак не собрался.

## Что должно быть

| Инструмент | Что делает | Обязанности |
| --- | --- | --- |
| `build-icons.mjs` | по `signs/<key>/icon.svg` собирает `signs/<key>/AppIcon.icns` и рендеры `icon-1024.png`, `preview-16.png`, `preview-32.png` | 10 записей (16…1024 при 1× и 2×); **один рендер и один штрих на все размеры**; малые размеры не перерисовываются |
| `check-icons.mjs` | распаковывает готовый `.icns` обратно и проверяет каждую запись | печатает по записи: размер, долю пикселей плиты, долю пикселей знака; пустая или шумная запись — **ненулевой код выхода** |

## Требования

* Работает без macOS: `iconutil` недоступен исполнителю, `.icns` пишется вручную.
* Зависимости — только из `npm`, зафиксированы (`package.json` + `package-lock.json`).
* Детерминированно: повторный прогон даёт побайтово те же файлы.
* Не тянет ничего из сети в момент сборки (кроме установки зависимостей).
* Эталон геометрии — `signs/dajet-player/` в `main`; канон — `CONCEPT.md` §1 и §4.

## Как это устроено

```
tools/
  build-icons.mjs      сборка
  check-icons.mjs      проверка
  lib/
    canon.mjs          канон из palette.json + таблица записей .icns
    icns.mjs           чтение и запись контейнера .icns
    render.mjs         рендер вектора (resvg) и увеличение без сглаживания
    pixels.mjs         разбор пикселей: плита / знак / чужой цвет
    svg-lint.mjs       линт вектора по канону
```

### Канон берётся из `palette.json`

Цвета, геометрия (канва 1024, плита 1024 без полей, штрих 92) и состав записей читаются из
[`../palette.json`](../palette.json) — инструменты не дублируют правила, они их
читают. Угол — `0.2253 × 1024 = 230.7072`; `canon.mjs` также отвергает
возврат старой сетки 824/74 в палитру. Если `palette.json` и таблица записей в `lib/canon.mjs` разойдутся,
сборка упадёт на старте, а не соберёт другой набор записей.

### Рендер: один вектор, один штрих, все размеры

Каждая запись `.icns` — рендер **того же** `icon.svg` на нужную сторону. Штрих
везде один и тот же (92 при канве 1024), круглые концы, никаких «оптически более
жирных» версий для мелких записей. Подмена штриха на малых размерах
запрещена независимо от их читаемости.

### Контейнер `.icns`

Магия `icns`, общая длина файла, затем записи: тип (4 байта) + длина (4 байта,
включая заголовок) + PNG. Десять записей:

| запись | тип | сторона PNG |
| --- | --- | --- |
| 16×16 | `icp4` | 16 |
| 16×16@2× | `ic11` | 32 |
| 32×32 | `icp5` | 32 |
| 32×32@2× | `ic12` | 64 |
| 128×128 | `ic07` | 128 |
| 128×128@2× | `ic13` | 256 |
| 256×256 | `ic08` | 256 |
| 256×256@2× | `ic14` | 512 |
| 512×512 | `ic09` | 512 |
| 512×512@2× | `ic10` | 1024 |

### Что проверяет `check-icons.mjs`

По каждой записи:

1. **Контейнер.** Ровно десять записей нужных типов, внутри — PNG ожидаемой
   стороны.
2. **Плита.** На месте и по геометрии: её габарит в записи равен `1024 × сторона / 1024`
   (допуск 1.5 px) — то есть плита 1024 без полей выдержана на всех размерах.
3. **Знак.** Доля знака в записи не ниже 2 %: запись не пустая.
4. **Шум.** Каждый пиксель проецируется на отрезок «плита → знак». Цвет, ушедший
   с отрезка, — чужой: его доля не может превышать 1 % непрозрачного. Так ловится
   именно «цветной шум», а не «маленькая картинка».
5. **Сверка с вектором.** Чекер перерисовывает `icon.svg` рядом на ту же сторону и
   сравнивает растр записи с этим рендером. Расхождение больше 0.02 означает, что
   запись нарисована не так, как вектор: штрих подменён, запись перерисована
   вручную или собрана другим рендерером. Это прямая проверка правила «малые
   размеры не перерисовываются».
6. **Линт вектора.** Ровно два цвета из палитры, никаких `<defs>`, градиентов,
   теней, прозрачности, штрих 92 с круглыми концами, канва 1024. У `<rect>`
   радиус скругления обязан быть валидным: отрицательный `rx`/`ry` или радиус
   больше половины меньшей стороны — ошибка.

Плюс к тому сам вектор проверяется **до сборки**: `build-icons.mjs` не собирает
знак, который канону не соответствует (знак, минующий канон, пропускается с
сообщением; собрать принудительно — `--force`). Именно поэтому при сборке
всех знаков `dajet-browser` пропускается: его вектор ещё на старой плите и в
старом цвете, это отдельная задача.

`--force` отменяет **стилистический** линт (цвета, градиенты, толщина штриха):
знак соберётся, но `check-icons.mjs` его всё равно не пропустит, и сборщик об
этом предупредит. Плита (канва 1024, плита 1024 без полей, по центру) обязательна всегда:
`--force` её не отменяет — без неё это не знак, а картинка.

### Пороги

| Порог | Значение | Почему |
| --- | --- | --- |
| доля знака в записи | ≥ 2 % | ниже — запись пустая |
| доля чужого цвета | ≤ 1 % непрозрачного | выше — «цветной шум» |
| габарит плиты | ±1.5 px от `1024 × сторона / 1024` | плита должна быть везде одной |
| расхождение с вектором | ≤ 0.02 | выше — запись нарисована иначе |

| Пакет | Зачем |
