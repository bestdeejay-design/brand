# tools — сборка и проверка иконок

Инструменты, которыми знаки из [`../signs/`](../signs/) превращаются в `.icns` и
проверяются. Одна реализация на весь зоопарк: знаки не должны собираться каждый
по-своему — именно так у плеера и появились две битые записи.

## Что должно быть

| Инструмент | Что делает | Обязанности |
| --- | --- | --- |
| `build-icons.mjs` | по `signs/<key>/icon.svg` собирает `signs/<key>/AppIcon.icns` и рендеры `icon-1024.png`, `preview-16.png`, `preview-32.png` | 10 записей (16…1024 при 1× и 2×); **один рендер и один штрих на все размеры**; малые размеры не перерисовываются |
| `check-icons.mjs` | распаковывает готовый `.icns` обратно и проверяет каждую запись | печатает по записи: размер, долю пикселей плиты, долю пикселей знака; пустая или шумная запись — **ненулевой код выхода** |

## Требования

* Работает без macOS: `iconutil` недоступен исполнителю, `.icns` пишется вручную.
* Зависимости — только из `npm`, зафиксированы (`package.json` + `package-lock.json`).
* Детерминированно: повторный прогон даёт побайтово те же файлы.
* Не тянет ничего из сети в момент сборки (кроме установки зависимостей).
* Образец — `dajet-player/media/icon.mjs` из PR #11: тип-коды и структура контейнера
  там верные. Новая реализация считается годной только тогда, когда `check-icons.mjs`
  разбирает контейнер **сам** и показывает по всем десяти записям и плиту, и знак.
  Важно: не проверяйте `.icns` через `iconutil` — на самодельных контейнерах он портит
  записи `icp4`/`icp5`, и это уже однажды стоило ложной блокировки PR (F-1).
