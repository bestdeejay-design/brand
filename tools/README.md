# tools — сборка и проверка иконок

Инструменты, которыми знаки из [`../signs/`](../signs/) превращаются в `.icns` и
проверяются. Одна реализация на весь зоопарк: знаки не должны собираться каждый
по-своему — именно так у плеера и появились две битые записи.

## Что должно быть

| Инструмент | Что делает | Обязанности |
| --- | --- | --- |
| `build-icons.mjs` | по `signs/<key>/icon.svg` собирает `signs/<key>/AppIcon.icns` и рендеры `icon-1024.png`, `preview-16.png`, `preview-32.png` | 10 записей (16…1024 при 1× и 2×); **один рендер и один штрих на все размеры**; малые размеры не перерисовываются |
| `check-icons.mjs` | распаковывает готовый `.icns` обратно и проверяет каждую запись | печатает по записи: размер, долю пикселей плиты, долю пикселей знака; пустая или шумная запись — **ненулевой код выхода** |

## Требования

* Работает без macOS: `iconutil` недоступен исполнителю, `.icns` пишется вручную.
* Зависимости — только из `npm`, зафиксированы (`package.json` + `package-lock.json`).
* Детерминированно: повторный прогон даёт побайтово те же файлы.
* Не тянет ничего из сети в момент сборки (кроме установки зависимостей).
* Образец для подражания и одновременно — что именно нельзя повторять:
  `dajet-player/media/icon.mjs` из PR #11. Он собрал `.icns` и попал в цель по
  формату, но его записи 16 и 32 вышли цветным шумом (находка F-1). Новая реализация
  считается годной только тогда, когда `check-icons.mjs` показывает по всем десяти
  записям и плиту, и знак.


## Реализовано: сборка линейных знаков

Node.js 22.12+, зависимости устанавливаются из корня через `npm ci`:

```sh
node tools/build-icons.mjs dajet-editor
node tools/check-icons.mjs dajet-editor
npm run icon:test
```

Без ключа обе команды выбирают `dajet-editor`. Сборка принимает вторым аргументом
выходную директорию, проверка — вторым и третьим аргументами пути к `.icns` и SVG.
Все пути по умолчанию вычисляются относительно скриптов, а не текущего каталога.

Общий pipeline — `icon-lib.mjs`: единый 4096px-мастер, Lanczos3, десять PNG-записей,
строгий разбор контейнера и сравнение всех RGBA-пикселей с векторным источником.
По каждой записи выводятся доли плиты и знака, включая отдельные колонки точных
RGB-совпадений. Допуск антиалиасинга и пороги описаны в
[`signs/dajet-editor/README.md`](../signs/dajet-editor/README.md#проверка-контейнера).

Валидатор SVG пока намеренно принимает только каноническую плиту и **один
непрерывный линейный знак** толщиной 74 — это редактор и эталон плеера.
Не объявляет легаси браузера, многоцветных котов или будущий многоконтурный
эквалайзер валидными: их схемы потребуют отдельного расширения валидатора,
но не отдельного способа растеризации или упаковки. Другие иконки этим PR
не пересобираются и не изменяются.

Проверка знака глазами всё равно обязательна. Автотесты содержат отрицательные
случаи (пустая/одноцветная запись, подмена знака, повреждения формата и канона).
Для редактора отдельный `previews/review.png` показывает натуральные размеры и
увеличения распакованных записей; фон этого листа не входит в палитру иконки.
